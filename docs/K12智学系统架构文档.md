## 1. 架构目标与约束

### 1.1 目标

| # | 目标 | 来源 |
|---|---|---|
| G1 | 以 AI 为核心的引导式学习：分步引导、严禁闲聊、不直接给答案 | PRD §1.2、§6.6 |
| G2 | 掌握式晋级闭环：完成练习 + 清空错题 → 解锁下一关 | PRD §6.1 |
| G3 | 数据自产出：爬虫采集 → 分析整理 → 结构化题库，支撑教学 | PRD §5 |
| G4 | 多模型接入、按学科/复杂度路由，成本可控、可切换 | PRD §6.6、§9 |
| G5 | 护眼与儿童可用：统一暖橘红配色、禁 emoji/吉祥物/装饰 | PRD §9、UX §1.2、style.md |
| G6 | 家庭自用起步，架构按多用户（多租户）预留 | PRD §1.3、§9 |

### 1.2 硬性架构约束

1. **配色唯一来源** [style.md](style.md)，前端 Token 映射 `app/web/src/styles/theme.css`，任何页面/组件不得自造颜色。
2. **AI 话题护栏是系统级约束**：所有 LLM 输出必须经过护栏管线，非学习话题一律温和拉回；对「直接索要答案」只给思路提示。
3. **单科先行**：MVP 仅数学开放，语文/英语在数据与界面层锁定。
4. **答疑拍照题不入错题本**；仅系统内练习/测验错题自动入本（PRD §6.2、§6.5）。
5. **base 层与 app 层技术栈解耦**：base 用 Python（数据生产），app 用 Node.js/TypeScript（业务服务），仅通过数据库与内部 HTTP API 交互。
6. 统一响应结构 `{code, data, message}`；LLM 流式输出走 SSE。

### 2.2 架构风格决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 服务形态 | **模块化单体**（NestJS 单应用内按限界上下文分模块），AI-Agent 中枢为独立模块且接口内聚，保留拆分余地 | 家庭自用期单人开发，微服务的运维成本不划算；模块边界清晰即可支撑后续产品化拆分 |
| 请求编排 | **所有业务请求经 AI-Agent 中枢编排**：需大模型回答的走 LLM 管线；章节/课程/学情等查询类请求由中枢做意图识别后调用领域服务查库、组装数据包返回 | 产品负责人明确要求（2026-10-13）；中枢统一承担「生成 vs 查询」的分流与数据组装，前端只面对一种对话式/资源式接口 |
| 跨语言协作 | base（Python）与 app（Node.js）通过 **PostgreSQL + paper-analysis 的 FastAPI HTTP 接口** 协作，无共享代码 | 技术栈解耦（约束 5）；错题上传链路需要同步-ish 的 HTTP 调用，纯共享库不够 |
| LLM 接入 | OpenAI 兼容协议为主的标准适配层 + 厂商特有协议适配器（如 Gemini），**路由策略配置化** | PRD §6.6 要求可切换；模型名与厂商迭代快，路由表进配置而非硬编码 |
| 实时性 | LLM 回复走 **SSE 流式**；其余 REST | 引导式对话对首字延迟敏感 |

## 3. 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 工程结构 | pnpm monorepo | `base/*`、`app/*` 各为独立包（已落地，TODO T0.1） |
| 前端 | React 18 + TypeScript + Vite + Tailwind CSS 4 | Token 变量体系支撑标准/夜间两模式（UX §3.1） |

| 后端 | Node.js 20 + NestJS 11 | 用户指定；代码位于 `app/server` |
| 数据库 | PostgreSQL 16 + Prisma（app 层 ORM） | base 层 Python 管道用 psycopg 直连；家庭自用期可降级 SQLite |
| LLM | OpenAI 兼容协议适配层 + 厂商适配器 | Kimi（Moonshot）/ Qwen3.7-Max（阿里）/ Gemini3.1-Pro（Google）/ DeepSeek-v4-flash |
| 爬虫 | Python：Scrapy + Playwright | 仅 base 层使用 |

| 公式/图表 | KaTeX、Recharts | style.md §6–7 |
| 定时任务 | NestJS Schedule（@nestjs/schedule） | 学情周报/月报定时生成、爬虫调度回调 |

## 4. 子系统详细设计

### 4.1 前端架构（app/web + Electron 壳）

#### 4.1.1 分层与目录约定

```
app/web/src/
├── main.tsx / App.tsx        # 入口、路由三区（登录 / 学生端 / 家长端）
├── styles/theme.css          # style.md 的 Tailwind Token 唯一映射（已预置）
├── api/                      # 后端接口封装（REST client + SSE client）
├── components/               # 通用组件（UX §5 规范：题目卡/AI 气泡/星球/打卡日历/休息遮罩）
├── features/                 # 按业务域组织：study/ mistake-book/ quiz/ qa/ reward/ parent/
├── pages/                    # 19 个页面对应的路由页面（UX §2.1）
├── hooks/                    # useTheme(模式切换)、useBreakTimer(护眼计时)、useFontSize(三档字号)
└── stores/                   # 轻量客户端状态（当前孩子、主题、字号、休息倒计时）
```

#### 4.1.2 路由与页面映射（对齐 UX §2.1）

| 路由区 | 页面 |
|---|---|
| `/auth` | P01 登录（按账号角色自动路由，无身份选择）、P02 首次使用向导 |
| `/student` | P03 首页、P04 章节星链图、P05 学习页、P06 错题本、P07 清错模式、P08 测评列表、P09 答题页、P10 测评报告、P11 作业答疑、P12 奖励中心、P13 设置 |
| `/parent` | P14 家长总览、P15 学情报告、P16 学习记录、P17 错题与薄弱点、P18 奖励管理、P19 家长设置 |

路由守卫：登录后按账号角色跳转对应区；跨区访问返回 403 页。

#### 4.1.3 关键前端机制

- **主题体系**：`html[data-mode="standard|night"]` 切换 CSS 变量；19:00 后自动建议夜间（UX §3.2）；学段仅影响字号（18/17/16px）与圆角/密度，配色全学段统一。
- **SSE 客户端**：封装 `EventSource`/fetch-stream，消费 AI-Agent 中枢的流式回复；断线自动重连。
- **护眼机制**：全局休息计时器（默认 30 分钟，家长可配 20/30/40）触发全屏遮罩；学习页常驻倒计时浮标。
- **低输入成本**：题干划选提问、选项点选 ≥48px、拍照上传（答疑与错题上传共用文件上传组件）。
- **公式与图表**：KaTeX 渲染 LaTeX（字号同正文）；Recharts 图表颜色只从 primary/success/warning 派生。
- **Electron 壳**：加载同一 Web 构建，提供 `←/→` 步骤切换、`Enter` 发送、`Esc` 关闭弹层全局快捷键。

### 4.2 应用服务层（app/server，NestJS 11）

#### 4.2.1 模块划分

```
app/server/src/
├── main.ts / app.module.ts
├── common/                  # 统一响应拦截器、全局异常过滤器、日志（已具备）
└── modules/
    ├── health/              # /api/health（已具备）
    ├── auth/                # 家庭账号 JWT 鉴权、角色（student/parent）路由依据
    ├── agent/               # ★ AI-Agent 中枢：编排、会话、护栏、判题（§4.3）
    ├── llm/                 # ★ 多模型接入层：Provider 适配器、路由表、用量统计（§4.3.3）
    ├── teaching/            # 教学系统：教材目录/章节/关卡/进度/晋级计算/打卡（§4.5）
    ├── mistake-book/        # 错题本：自动收录、手动上传、清错、薄弱点（§4.6）
    ├── admin/               # 家长与管理：学情聚合、定时报告、奖励、配置（§4.7）
    └── content/             # 内容查询服务：题目/课程框架/知识点（供 agent 编排与各模块复用）
```

> `app/agent`、`app/teaching-system`、`app/mistake-book`、`app/admin` 目录为**领域说明与规格存放处**（README 已就位），实现代码统一收敛在 `app/server/src/modules/*`。

#### 4.2.2 请求处理总流程（中枢编排模型）

```
Web 客户端 ──REST/SSE──► NestJS 网关层（鉴权/参数校验/统一响应）
                              │
                              ▼
                      AI-Agent 中枢（编排器）
            ┌───────────────────┴───────────────────┐
            ▼                                       ▼
     生成类请求（需大模型）                     查询类请求（数据获取）
     引导教学/答疑/评阅/学情报告              章节/课程/关卡/错题/学情
            │                                       │
            ▼                                       ▼
     护栏管线 → 模型路由 → LLM API            调用 content/teaching/mistake-book
            │                                       等领域服务查 PostgreSQL
            ▼                                       │
     SSE 流式返回 ◄──────── 组装数据包（统一 DTO）◄─┘
```

- **生成类**：中枢按场景装配上下文（教学框架、当前题目、对话历史、学段语言风格），经护栏管线后交多模型接入层。
- **查询类**：中枢做意图识别（规则 + 轻量 LLM 分类兜底），路由到对应领域服务的查询方法，将结果组装为统一结构的数据包返回。此路径**不经过 LLM**（除非需要自然语言总结，如首页学习建议），以保护成本与延迟。
- 判定规则可配置：`POST /api/agent/chat` 类接口默认走生成管线；`GET /api/content/**` 等资源接口直接由领域模块响应（经同一鉴权/响应规范），保证简单查询不被中枢放大延迟。

### 4.3 AI-Agent 中枢（modules/agent + modules/llm）

#### 4.3.1 职责

1. **编排**：接收生成类请求，装配上下文、选择场景 Pipeline、调用模型、处理流式回传。
2. **多模型路由**：按「学科 × 复杂度」选择模型（§4.3.2）。
3. **话题护栏**：输入侧 + 输出侧双向约束（§4.3.4）。
4. **会话管理**：对话上下文窗口、教学框架注入、会话持久化（家长端可回看，PRD §8）。
5. **判题辅助**：客观题精确判分；主观题 LLM 评阅（评分 + 评语）写回答题记录（TODO T3.4）。
6. **用量与降级**：token 统计、按模型成本核算、失败自动降级到备选模型。

#### 4.3.2 多模型路由策略（配置驱动）

路由表存于配置（`app/server/.env` + DB 配置表），按优先级匹配：

| 优先级 | 条件 | 模型 | 说明 |
|---|---|---|---|
| 1 | 学科=数学 且 复杂度=高（多步推导/证明/压轴题） | **Gemini3.1-Pro** | 复杂数学推理 |
| 2 | 学科=数学 且 复杂度=常规 | **Qwen3.7-Max** | 常规数学引导 |
| 3 | 学科=语文/英语（语言类任务） | **Kimi** | 长文本与语言学科 |
| 4 | 其余（一般问题、闲聊拉回、简单判阅） | **DeepSeek-v4-flash** | 低成本快速响应 |

- 复杂度判定：题目元数据（难度字段、知识点层级）优先；无元数据时由 flash 级模型做一次轻量分类。
- **降级链**：主模型超时/失败 → 同场景备选模型 → 兜底 flash 模型；全程记录降级事件。
- **成本控制**：预制教学框架减少实时 token（PRD §9）；每会话/每日 token 配额；用量按家庭/学生统计入库，供家长端查看。

#### 4.3.3 多模型接入层（modules/llm）

```
LLM Gateway
├── ProviderAdapter（接口）：chat(messages, options): AsyncIterable<chunk>
│   ├── OpenAICompatAdapter   # DeepSeek、Kimi(Moonshot)、Qwen(DashScope 兼容端)
│   ├── GeminiAdapter         # Gemini 原生协议（或其 OpenAI 兼容端点）
│   └── (可扩展)
├── ModelRouter               # 路由表匹配、降级链执行
├── UsageTracker              # prompt/completion tokens、耗时、成本核算 → DB
└── StreamNormalizer          # 各厂商流式格式 → 统一 SSE 事件（delta / done / error）
```

接入层只暴露统一接口，业务模块不感知具体厂商；新增模型 = 新增一个 Adapter + 路由表配置。

#### 4.3.4 话题护栏管线（PRD §6.6 硬约束）

```
输入侧                          模型侧                     输出侧
用户消息 ─► 索答检测     ─►  系统提示词（护栏 +    ─►  话题相关性校验（flash 模型
（直接要答案？套话？）        教学框架 + 分步引导        或规则分类）：是否偏离学习
    │                        策略 + 学段语言风格）      话题 / 是否泄露完整答案
    ├─ 索答 → 改写为思路提示请求                  │
    └─ 正常 → 注入上下文                          ├─ 偏离 → 追加「温和拉回」指令重新生成
                                                 └─ 通过 → SSE 流式下发
```

- 索答对抗：提示轮次未用尽时，任何形式的索答（直接要、装可怜、角色扮演）统一降级为「提示 1/3」；轮次用尽后按家长配置开放完整解析（P11）。
- 10 组诱导测试用例作为护栏回归测试（TODO T3.3 验收标准）。

#### 4.3.5 场景 Pipeline

| Pipeline | 触发 | 上下文注入 | 输出 |
|---|---|---|---|
| guided-learning 引导教学 | P05 学习页对话 | 该课教学框架 + 当前步骤/题目 + 已错记录 | 分步引导流式回复 |
| qa-homework 作业答疑 | P11 拍照/文字 | OCR 文本 + 家长配置的引导轮数 | 引导对话，超轮次后开放解析 |
| grading 判题 | 作答提交 | 题目 + 标准答案 + 学生答案 | 客观题精确判分 / 主观题评分+评语 |
| mistake-explain 错题讲解 | P06「听小智讲解」 | 错题快照 + 历史错误 | 针对性讲解 |
| report 学情报告 | 家长端 P15 / 定时任务 | 周期学情聚合数据 | AI 周报/月报（Markdown 存储） |

### 4.4 数据生产层（base，Python）

#### 4.4.1 网络爬虫系统（base/paper-crawler）

- **输入**：站点适配器配置（试点：1 个数学试卷站，TODO T2.2）。
- **流程**：调度器（增量抓取）→ Scrapy/Playwright 抓取 → 试卷/题目/答案/解析解析 → 图片与公式资源本地化 → 原始数据落库（raw 表）→ 失败重试队列。
- **输出**：原始 PDF/图片 + 未结构化文本，交数据分析与整理系统。
- **合规**：仅家庭自用；控制抓取频率；产品化前解决版权（PRD §10）。

#### 4.4.2 数据分析与整理系统（base/paper-analysis）

对外以 **FastAPI HTTP 服务** 常驻（供错题上传等在线链路调用），同时支持离线批处理管道。

```
输入：PDF / 图片
  │
  ▼
① 文档解析：PDF 版面分析 / 图片 OCR（可对接多模态 LLM 提升手写体识别）
  │
  ▼
② Markdown 化：整卷/整页转 Markdown（LaTeX 公式内联）
  │
  ▼
③ 题目切分：按题号/版面特征切分为单题记录（题干/选项/答案/解析/配图）
  │
  ▼
④ 结构化清洗：题型识别、难度估计、去重（文本指纹 + 相似度）、图片关联
  │
  ▼
⑤ 知识点标注：LLM 批量标注 → 课标知识点树；抽样人工校验工作台
  │
  ▼
⑥ 内容预制：按课生成教学框架（学习目标/讲解要点/例题序列/练习题组）
  │
  ▼
入库：PostgreSQL（psycopg 直连；状态机：raw → structured → annotated → published）
```

**在线接口（供 app/server 调用）**：

| 接口 | 用途 | 调用方 |
|---|---|---|
| `POST /parse/document` | 上传图片/PDF → Markdown → 拆题 → 结构化（同步小文件 / 异步任务+回调） | 错题本系统（P06 手动上传） |

### 4.5 教学系统（modules/teaching）

- **课程模型**：教材版本 → 年级 → 单元 → 章节（含重要度 大/中/小，驱动星链图星球尺寸）→ 小节（课）→ 关卡（一课一关）。
- **晋级计算（掌握式）**：`关卡解锁 = 前置关卡完成 ∧ 本关练习完成 ∧ 本关错题清空`；`单元解锁 = 本单元全部关卡完成 ∧ 单元错题清空`。解锁逻辑收敛为独立领域服务并做单测覆盖（TODO T4.2 验收）。
- **三模式**：同步（按解锁链）/ 预习（后续章节临时可进）/ 复习（已学章节可重学）。
- **打卡**：学习行为触发当日打卡，连续天数计算（跨天边界单测）。
- **星链图数据接口**：向中枢提供章节星球数据（章节、重要度、状态、解锁条件），前端渲染 88/68/52px 三档星球（style.md §3）。

### 4.6 错题本系统（modules/mistake-book）

#### 4.6.1 错题来源

| 手动上传 | P06 上传图片/PDF → server 接收 → **调 paper-analysis `/parse/document`** → Markdown → 拆题 → 结构化入库 → 返回题目信息 → 错题本建立记录 | 本版新增链路，见 §4.6.2 |
| 作业答疑 | P11 拍照答疑 **不入错题本** | PRD §6.5 明确排除 |

#### 4.6.3 清错与薄弱点

- **清错**：重做答对或 AI 确认掌握 → 清除；清错状态实时反馈给教学系统解锁计算。
- **薄弱点分析**：按知识点聚合错题分布 → 薄弱点排名 → 驱动变式题再练推荐（依赖 T2.5 变式关联）。
- **周期复习**（P2）：遗忘曲线推荐已清错题回顾。

## 7. 接口设计约定

- **前缀**：`/api`；统一响应 `{code, data, message}`（code=0 成功），全局异常过滤器兜底（已具备）。
- **鉴权**：JWT Bearer；payload 含 `userId, role(student|parent), familyId, studentId?`；角色不符返回 403。
- **流式**：`POST /api/agent/chat` 返回 `text/event-stream`，事件：`delta`（增量文本）、`meta`（模型/用量）、`done`、`error`。
- **文件上传**：`multipart/form-data`，限制大小与类型（图片 jpg/png/webp、PDF）；暂存本地文件目录，路径入库存引用。
- **错误码**：模块前缀式（如 `AGENT_1001` 护栏拦截、`LLM_2001` 全部模型不可用、`PARSE_3001` 解析失败），前端按 code 做友好提示。

## 8. 非功能架构

| 维度 | 方案 |
|---|---|
| 安全与内容安全 | JWT + 角色路由；LLM 输出过护栏管线；未成年人数据仅家庭内可见（familyId 隔离）；上传文件类型/大小白名单 |
| 护眼合规 | 前端 Token 唯一来源 style.md；无 emoji/吉祥物/装饰；动效 ≤200ms、奖励动效 ≤3s 可跳过；学习页常驻休息倒计时 |
| 性能 | LLM 首 token 目标 <2s（SSE）；查询类接口 P95 <300ms（索引：familyId+状态、知识点、章节）；预制框架降低生成延迟 |
| 成本 | 模型分级路由（flash 处理低价值调用）；token 配额与用量看板；预制内容减少实时生成 |
| 可观测 | 结构化日志（请求 ID 贯穿）；LLM 用量/降级事件入库；护栏拦截率统计 |
| 部署 | docker-compose：`postgres` + `server` + `web(nginx 静态)`；base 管道独立 Python 环境（手动/定时触发）；`.env` 管理各模型 API Key，不入库不入 git |
| 备份 | PostgreSQL 每日 pg_dump；上传文件目录同步备份 |

## 11. 架构风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 中枢编排单点过载（所有请求经中枢） | 查询延迟被放大 | 简单资源查询直连领域模块（§4.2.2），中枢仅编排生成类与需组装的复合查询 |
| 模型名/厂商变动频繁 | 路由失效 | 路由表配置化 + Adapter 抽象，换模型只改配置（§4.3.2–4.3.3） |
| 护栏被孩子绕过 | 违背教育目标、内容风险 | 输入/输出双向校验、诱导用例回归测试、家长端对话可查（§4.3.4） |
| 上传解析质量不稳（手写/拍糊） | 错题收录错误 | 拆题结果前端可确认可编辑后再落库（§4.6.2）；解析失败降级为原图+人工修题 |
| 爬虫版权与站点变动 | 内容断供/合规风险 | 自用期控制传播；适配器配置化便于换站；产品化前采购授权（PRD §10） |
| LLM 成本失控 | 家庭使用成本上升 | 分级路由 + 配额 + 用量统计看板（§4.3.2、§8） |
